**地址怎么来的**：`vite.config.ts` 里 host 取 `.env` 的 `N_HOST`，默认 `127.0.0.1`（只听本机）。
现在 `.env` 里是 Tailscale 那张网卡（`100.106.43.81`），所以只能从这个 IP 进 —— 换成公网 IP 一律拒绝连接。
改 `.env` 的 `N_HOST` 换监听地址（`0.0.0.0` = 全开），下面的链接跟着换前缀。

两种起法，二选一，不能同时（`strictPort` 开着，第二个会直接报端口被占）：

```bash
npm run build && npm run preview   # 吃 dist，改了要重新 build
npm run demo                       # = vite，dev server 也在 4783，改 demo 立刻生效
```

**加了新 demo 不用改配置**：扔一个 `demo/<名字>/index.html` 进来，`vite.config.ts` 里的
`demoInputs()` 扫目录自动进构建，产物落在 `dist/demo/<名字>/`。

## 1. button —— 19 个悬浮操作动效

块平时是干净的；鼠标进块（或键盘 Tab 进去）才浮出按钮。按钮不占布局、不推文字，只动
`transform / translate / scale / opacity`。**按钮点了什么都不发生** —— 这里只交付动效。

- http://100.106.43.81:4783/demo/button/index.html

页面上的开关：`全部展开`（也可以直接进 `…?pin`）、`显示热区`（蓝框 = 行，红框 = 浮层真实边界）、
`浅色 / 深色`（走 app 的 token）、顶部编号只看某一个方案。

看的时候重点看四件事：

1. 光标在行里横着扫一遍：**名字、数值一个字都不能跳**。跳了就是布局被动到了。
2. 光标移到按钮上再移回行里：**不能闪、不能重播**。热区要连成一片。
3. 进出各来二十次：**进场慢、退场快**。退场跟进场一样慢 = 迟钝；退场带过冲 = 犹豫。
4. 连按二十次按钮：按下要**立刻**有反应（90ms 内），过冲只准出现在「出现」上。

**如果只让四个活下来**：`10 慢悬停`、`09 长按`、`15 贴名字`、`01/08 二选一`。
`07 三点 → 菜单` 在动作超过 3 个时顶掉上面任何一个。

复用：三个文件，没有依赖。

```
demo/button/index.html   页面骨架 + 三个开关
demo/button/demo.css     全部样式（变量在最上面，每个方案一个 .vNN 命名空间）
demo/button/main.js      19 个方案的 DOM + 八个需要 JS 的行为（长按/磁吸/菜单/跟随…）
```

搬走一个方案：复制 `demo.css` 里那段 `.vNN …`（每段都标了「形状 / 差异点 / 代价」）→ 换前缀 →
把 `.acts` 放进**行元素内部**（绝对定位），`pointer-events` 用 `:hover` 开关 ——
这是「不闪」的关键：光标从行移到按钮上不能触发「离开行」。

## 2. id —— 12 种给节点起 id 的办法

- http://100.106.43.81:4783/demo/id/index.html

同一棵树、同一串操作（插一块 / 删中间 / 改组名 / 搬走一支 / 重开），十二种 id 规则同时重算。
每格里是这个 id **现在**长什么样。三条判据：

- **稳定** —— 改完结构，同一个 id 还认得出同一块吗（变了 = 麻烦，**指错人 = 灾难**：它不报错，它静静地让你改了另一块）
- **套娃** —— 子 id 是不是以父 id 开头（是的话 `startsWith` 就等于「我这一整支」）
- **可念** —— 人能不能在群里打出来、在电话里念出来

结论：**段路径**（每段是节点自己的不可变短 id，父子靠前缀相连）是唯一两边都占一点的 ——
关系真在 id 里，而每一段永不改变；代价是长，和「搬家就换地址」。
落地建议是三个字段各管一件事：`segPath` 给人看和寻址 + 一条不可见的 `uid` 兜底 + `name` 只做显示。

反直觉的一点：压到「重开」那一步，**指错人的不止序号派** —— 名字路径、序号路径、内容 hash 一样会。
因为它们的 id 是确定性的：两盘结构一样的棋算出同一串 id，A 盘的链接在 B 盘上安静地打开另一块。
随机派、段路径、名字@段、双标识全身而退 —— 它们跟「第几个」「叫什么」都没关系。

## 3. button-on-tree-map —— 13 号层叠卡片装在真行上

- http://100.106.43.81:4783/demo/button-on-tree-map/index.html

对照表是白盒，这个是长在真行上的 —— 直接渲染 `src/App`，同一份组件、同一份数据、同一份 CSS，
动作按钮靠运行时挂到左列每一行（**一行 src 都不用改**）。四个按钮是空操作，不会写盘。

它和主应用读同一个 content 目录、走同一个 `/api/boards`，所以 demo 里加块改名，主盘跟着变（反过来也一样）。

只挂了左列的行。盘面上的块没挂 —— 块会被布局挤到 30px 见方，一摞按钮塞不进去；那种尺寸该用 07 号菜单。

## 4. menu-on-tree-map —— 07 号三点菜单装在真盘上

> **07 号已经进 `src/` 了**（`src/NodeMenu.tsx` + `src/menu.css`），真身自己就有这颗 •••。
> 这个 demo 目录保留下来只当对照 —— 它靠运行时注入，会和真身那颗打架（同一行两颗 •••）。
> 想看干净的效果，直接开 http://100.106.43.81:4783/

- http://100.106.43.81:4783/demo/menu-on-tree-map/index.html

同一个菜单挂两个地方 —— **左列的行**和**盘面上的块**。这是 07 存在的理由：
三个以上动作就不该排一排图标，尤其块会被布局挤到 30px 见方，一排按钮根本塞不下。

- 行上：22px 玻璃 `•••`，顶掉了应用自带那个 `×`（一行两个删除太蠢）。
- 块上：`•••` 贴在块的右上角，尺寸跟着块走（`data-size` = 14 / 17 / 20px），
  颜色抄应用自己那个 `×` 的做法压一层黑 —— 块的颜色五花八门，玻璃压不住。
- 菜单是 `position: fixed` 的。**这是 07 能上块的关键**：块那层 `overflow: hidden` 切不掉它。
- 靠右会往左收，下面放不下会往上开（`transform-origin` 跟着翻），不探出视口。
- `Esc` 关、点外面关、滚一下也关（菜单跟着滚动会跟按钮脱节，关掉比让它漂着强）。

注入的条目全是空操作，不写盘。`src/` 一行没改。

## 谁依赖构建，谁不依赖

`button` 和 `id` 的入口是纯 `.js`，拷走就能用。
`button-on-tree-map` 和 `menu-on-tree-map` 的入口是 `.tsx`，还 import 了 `src/App`、`src/tokens/*.css` ——
那就不只是静态文件了，得跟主应用一起过构建。

材质全部从 token 里 `color-mix` 出来（`--glass-bg` 等），换调色板不用回来改。

## 已知边界

- `12 径向`、`17 底部抽屉` 会让 `.panel` 的 `overflow` 变成 `visible` —— 它们本来就该溢出。
- `15 贴名字` 在 `pointerenter` 时量一次名字宽度；字体晚到或窗口变了会重新量。
- `18 液体融合` 的 `backdrop-filter` 被 goo 吃掉了，所以它是实色不是玻璃 —— 故意的。
- 触屏上 `01–08`、`10–13`、`15–19` 都不会出现（没有 hover）。要用触屏，看 `09` 或 `14`。
- demo 不进 PWA 预缓存（`vite.config.ts` 里的 `globIgnores`）：它们是给人看的实验页，
  每个都带着一整份 `src/App`。`navigateFallbackDenylist` 挡掉 `/demo/`，不然刷新会被 SW 塞回主应用的壳。
